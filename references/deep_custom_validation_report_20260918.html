问题与原因

主唤醒索引约束

02、03、05、07 的唤醒 mainE2E=false，stage1 报 result_main_reshape_idxs_([0]) != result_main_reshape_idxs([0, 15])。这是当前资源生成器的结构约束；若业务允许所有唤醒通路关闭，需要平台修复或在 UI 提交前明确阻止。

自定义词控件边界

20 缺少自定义命令词 ASRFree，21 缺少自定义唤醒词 mainE2E，23 缺少自定义子词 ASRFree。U/V 的 E2E 并非缺失，已在 22 成功验证。三项均未进入有效平台构建。

平台升级建议

  1. 升级后先重新执行未提交 smoke，不直接继承历史能力结论。
  2. 能力目录明确返回自定义词各专用通路的 Supported/Unsupported。
  3. 在 UI 阶段明确 mainE2E 全关的业务规则或修复 stage1 索引生成。
  4. 每个成功包继续保留 web_config 和四词表逐词断言。
  5. 打包 PASS 后另行执行烧录和真机运行验证。
