# 平台固件最小组合打包策略

本文档用于后续平台固件打包验证时设计“最少包数覆盖最多配置项”的测试矩阵。适用于产品管理 -> 固件打包的 UI 配置、算法模板导入、固件产物和后续真机验证。

从 2026-06-12 起，平台固件打包主链路强制按 UI-only 执行：产品创建/复用、基础配置、算法导入、深度调优、生成打包都必须由浏览器 UI 触发。历史 API 参数、隐藏产品壳、直接写 payload 打包只允许作为单独的接口健壮性探测，不允许计入 UI 打包主结论。

## 核心原则

- 严格以 UI 当前可选项为准：页面能选什么就打什么，不允许使用历史 API 参数强行创建 UI 不可选的产品、垂类或版本。
- 每次执行都必须实时读取 UI 下拉、卡片和联动结果；历史 options、CSV、截图和上轮计划只能做设计参考，不能作为脚本死数据。
- 一个垂类固定一个代表品类；同一产品下生成多个 release，不为每个配置单独创建产品。
- 如果平台为空或目标产品不存在，必须通过 UI 新建一个产品，再在该产品下继续创建不同配置 release。
- 每个 release 必须填写短版本描述，只写当前配置向量，例如 `默认+指定唤醒`、`左边界+循环唤醒`、`右边界+协议唤醒`、`默认+指定学习+指定唤醒`、`关闭隔离`。不要写长产品名、长版本号或完整用例说明。
- 第一个包优先验证“默认主链路”：基础配置保持默认，只开启当前产品支持的专项能力，并导入匹配的算法模板。
- 后续包只修改高价值可选项：唤醒时长、音量挡位、唤醒词断电保存、音量掉电保存、主被动协议、语音注册模板数/失败重试次数、语音注册模式、多唤醒模式。
- 数值类最多取三个代表值：默认/中值、左边界、右边界；禁止为了每个数字单独打包。
- 功能选择类必须覆盖互斥模式：例如语音注册的指定学习/连续学习，多唤醒的指定切换/循环切换/协议切换。
- 能共存的配置合并到同一个包；只有互斥配置、关闭反例或问题收敛才额外拆包。
- 灵敏度、字数上下限默认不改，除非需求明确要求验证这类参数。
- 算法模板不是固定附件，必须随包的验证目标调整词条、泛化词、协议、播报和专项数据。

## 可修改的基础配置

基础配置只围绕以下四类做组合覆盖：

| 参数 | 覆盖方式 | 说明 |
| --- | --- | --- |
| 唤醒时长 | 默认值 + 左边界 + 右边界 | 分散到 3 个包，不逐值枚举。 |
| 音量挡位 | 默认值 + 左边界 + 右边界 | 例如 10 级音量取默认/1/10。 |
| 唤醒词断电保存 | true/false | 和基础边界包组合，不单独打包。 |
| 音量掉电保存 | true/false | 和基础边界包组合，不单独打包。 |

其他基础项原则上保持默认；只有协议口波特率或日志等级是本轮验证目标时，才和边界包一起调整。

## 算法模板可覆盖项

算法模板至少要承担以下覆盖，不应只满足“能导入”：

| 类型 | 建议覆盖内容 |
| --- | --- |
| 基础词条 | 默认唤醒词、业务命令、音量上/下/最大/最小/中等、退出识别。 |
| 泛化词 | 父泛化词、子泛化词、常用同义说法；用于验证模板解析和打包落地。 |
| 功能类型 | 唤醒词、命令词、音量词、退出识别、唤醒词负性词、命令词负性词、欢迎语、播报语、休息语、心跳协议。 |
| 播报 | 主播报、被动播报、主被组合；播报语要和垂类语义一致。 |
| 协议 | 命令词发送协议、被动接收协议、播报语协议、心跳协议。 |
| 多唤醒 | 默认唤醒词、候选唤醒词、查询、恢复默认、指定切换、循环切换、协议切换字段。 |
| 语音注册 | 学习/删除/退出/全部删除控制词、可学习目标命令、注册过程播报和协议。 |

模板词条必须符合当前垂类语义，例如窗帘垂类使用 `打开窗帘`、`关闭窗帘`、`停止窗帘`，不要保留其他垂类的业务词导致设备验证失真。

## 四类产品打包矩阵

### 1. 只有基础功能

| 包 | 页面配置 | 算法模板 | 目标 |
| --- | --- | --- | --- |
| 包 1 默认基础包 | 基础配置全默认 | 基础完整模板：唤醒、业务命令、音量、退出、负性词、欢迎/播报/休息/心跳、主被动协议 | 验证默认主链路可用。 |
| 包 2 左边界包 | 唤醒时长左值、音量挡位左值、保存关闭 | 强化泛化词、负性词、主动协议 | 覆盖基础低边界和主动协议。 |
| 包 3 右边界包 | 唤醒时长右值、音量挡位右值、保存开启 | 强化被动播报、被动协议、心跳协议 | 覆盖基础高边界、保存项和被动链路。 |

### 2. 支持多唤醒

| 包 | 页面配置 | 算法模板 | 目标 |
| --- | --- | --- | --- |
| 包 1 默认 + 指定切换 | 基础配置默认；开启多唤醒；模式选指定切换 | 基础完整模板 + 候选唤醒词 + 指定切换词 + 查询/恢复默认 | 验证多唤醒主链路。 |
| 包 2 左边界 + 循环切换 | 基础左边界；保存关闭；模式选循环切换 | 候选唤醒词、循环切换、主动协议、负性词 | 覆盖循环模式和基础低边界。 |
| 包 3 右边界 + 协议切换 | 基础右边界；保存开启；模式选协议切换 | 候选唤醒词协议字段、被动播报、心跳协议 | 覆盖协议切换、基础高边界和保存项。 |

### 3. 支持语音注册

| 包 | 页面配置 | 算法模板 | 目标 |
| --- | --- | --- | --- |
| 包 1 默认 + 指定学习 | 基础配置默认；开启语音注册；模式选指定学习；注册模板数/重试次数默认 | 基础完整模板 + 注册控制词 + 可学习目标命令 | 验证语音注册主链路。 |
| 包 2 左边界 + 连续学习 | 基础左边界；保存关闭；模式选连续学习；模板数/重试次数取低值 | 连续学习目标命令、删除命令、退出命令、主动协议 | 覆盖连续学习和注册低值。 |
| 包 3 右边界 + 指定学习高值 | 基础右边界；保存开启；模式选指定学习；模板数/重试次数取高值 | 指定学习目标命令、被动播报、协议、心跳 | 覆盖指定学习高值、保存项和协议链路。 |

### 4. 同时支持语音注册和多唤醒

| 包 | 页面配置 | 算法模板 | 目标 |
| --- | --- | --- | --- |
| 包 1 默认 + 双功能主链路 | 基础配置默认；语音注册开启；多唤醒开启；语音注册指定学习；多唤醒指定切换 | 综合模板：基础词条 + 主被动协议 + 多唤醒词 + 语音注册控制词 | 验证最大能力集默认链路。 |
| 包 2 左边界 + 连续学习 + 循环切换 | 基础左边界；保存关闭；语音注册连续学习；多唤醒循环切换；模板数/重试次数低值 | 连续学习目标词、循环切换词、主动协议、负性词 | 覆盖两个能力的第二模式和低边界。 |
| 包 3 右边界 + 指定学习高值 + 协议切换 | 基础右边界；保存开启；语音注册指定学习高值；多唤醒协议切换 | 协议切换候选唤醒词、被动播报、心跳协议、主被动协议 | 覆盖协议模式、高值和保存项。 |

若需求明确要求“功能关闭反例”，增加第 4 包：关闭语音注册和/或多唤醒，验证控制词不生效、基础链路仍正常。主流程打包覆盖不强制包含关闭反例。

## 3021 固定产品最小矩阵执行口径

- 先在 UI 中选择 `CSK3021` 支持的垂类；每个垂类只固定一个代表品类，例如茶吧机/智能窗帘/风扇/取暖器/取暖桌/智能垃圾桶。
- 对每个固定产品创建一个产品记录；该产品下按能力生成多个 release：
  - 仅基础或仅多唤醒能力：默认包、左边界包、右边界包，通常 3 个 release。
  - 同时支持语音注册和多唤醒：默认双功能包、左边界连续学习+循环切换包、右边界指定学习高值+协议切换包、关闭隔离包，通常 4 个 release。
- 包数不是固定值。若 UI 不支持某能力，必须裁剪；若 UI 新增能力或用户要求关闭反例，按同一原则增加最少必要包。
- 配置完成点击“生成并关闭”后立即进入下一个 release；全部提交后统一轮询后台状态。
- 版本描述必须作为提交证据保存；若 UI 当前没有描述输入框或无法编辑，记录 `version_description_ui_not_exposed`，不得通过 API 补写后记为 UI 成功。
- 打包成功后，真机验证必须反向读取该 release 的实际配置：协议波特率、日志等级、音量档位、保存项、多唤醒模式、语音注册模式/重试次数/模板数。测试什么包，就只按该包启用的能力闭环验证，不混用其他包的预期。

## 上限为 3 时的数据匹配

### 多唤醒模板上限 3

当多唤醒候选上限配置为 3，模板与 UI 必须匹配：

- 1 个默认唤醒词，例如 `小聆小聆`。
- 3 个候选唤醒词，例如 `小优小优`、`小乐小乐`、`小智小智`。
- 查询、恢复默认、切换唤醒词等公共控制命令。
- 指定切换模式下，必须有 3 条指定切换命令。
- 协议切换模式下，3 个候选词必须分别配置协议字段。

示例：

| 候选 | 唤醒词 | 指定切换命令 | 协议字段 |
| --- | --- | --- | --- |
| 默认 | 小聆小聆 | 恢复默认唤醒词 | 默认唤醒协议 |
| 候选 1 | 小优小优 | 切换到小优小优 | 候选 1 snd/rec |
| 候选 2 | 小乐小乐 | 切换到小乐小乐 | 候选 2 snd/rec |
| 候选 3 | 小智小智 | 切换到小智小智 | 候选 3 snd/rec |

### 语音注册模板上限 3

当语音注册模板数配置为 3，模板与 UI 必须匹配：

- 注册控制词：学习命令词、学习唤醒词、删除命令词、删除唤醒词、删除全部命令词、退出学习、退出删除。
- 3 个可学习目标命令，例如 `打开窗帘`、`关闭窗帘`、`停止窗帘`。
- UI 中选择的可学习目标命令必须来自导入模板，不能填模板外的词。
- 运行态验证时再学习 3 条新别名，新别名不应预先写进模板。

示例：

| 目标命令 | 运行态学习新词 | 说明 |
| --- | --- | --- |
| 打开窗帘 | 拉开窗帘 | 绑定到打开动作。 |
| 关闭窗帘 | 合上窗帘 | 绑定到关闭动作。 |
| 停止窗帘 | 窗帘暂停 | 绑定到停止动作。 |

指定学习需要在 UI 中显式选择 3 个可学习目标；连续学习也需要模板提供 3 个可学习目标，但设备侧流程按固件状态机执行。

## 模板负例规则

- 负性词不能使用语音注册控制词、多唤醒切换词、删除词、退出词。
- 负性词不能触发真实业务功能，否则会污染功能链路判定。
- 学习/删除类控制词只能用于语音注册专项流程，不能混作普通命令负例。

## 执行与报告规则

- 同一产品下生成多个 release，不为每个配置新建产品。
- 点击“生成并关闭”后立即继续提交下一个包，不能逐包等待后台完成；全部提交后统一轮询 release 状态。
- 报告必须列出每个包覆盖了哪些页面参数和哪些模板字段。
- 如果组合包失败，先不要扩大矩阵；用控制变量法新增最小依赖包定位问题。
- 如果 UI 不暴露某个能力或参数，记录为 UI 当前不支持，不允许用 API 强写后混入 UI 主结论。
