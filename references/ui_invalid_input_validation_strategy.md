# UI 异常参数过滤验证策略

## 目标

用于验证平台前端能否在真实 UI 操作路径下阻断异常输入，防止异常配置进入固件打包、音频合成或播报合成流程。该策略只统计浏览器 UI 触发证据；只读接口可用于登录态、菜单和枚举确认，不能代替页面输入和点击。

## 执行原则

- 新建专项产品或专项记录，名称使用 `AUTO_UI_INVALID_*` 或明确的“异常参数验证”后缀，避免复用正例打包产品。
- 通过 UI 打开表单、输入异常值、选择文件、点击保存/继续/导入，不直接调用写接口构造异常 payload。
- UI 页面不可填写、不可选择、不可提交的参数不得伪造成用例；如需探测后端健壮性，单独标记为 `api_probe`，不能写入 UI 主结论。
- 异常用例要基于正常配置推导，避免无业务意义的随机脏数据；每条异常必须写明测试意图。
- 若异常被前端组件自动改写为合法值，应记录为“已清洗/重置”，不能简单写通过或失败。
- 若前端无明确提示但不提交、不进下一步，应记录为“静默拦截/提示不足”，并说明用户可感知性不足。

## 推荐分类

| 分类 | 判定 |
|---|---|
| `PASS_REJECTED` | UI 给出明确错误提示并阻止继续。 |
| `PASS_SANITIZED` | UI 将异常值重置、裁剪或清洗为合法值，并未让异常值进入后续配置。 |
| `RISK_ACCEPTED` | UI 保留异常值并保存/继续成功，需作为前端过滤不足风险。 |
| `RISK_SILENT` | UI 没有明确错误提示，用户无法判断失败原因。 |
| `UNSUPPORTED_REASONABLE` | 不支持能力在页面不可见、不可开启或被合理门控。 |
| `SCRIPT_LIMITATION` | 当前自动化无法通过真实 UI 完成该动作，需要人工 UI 补测，不能写为功能通过。 |

## 固件打包异常项

每个 3021 支持垂类选择一个代表品类并新建专项产品，在“快速创建”中验证：

- 基础配置：默认音量超范围、非数字输入、保存项联动。
- 播报配置：欢迎语/合成文本的脚本字符、emoji、超长文本。
- 算法配置：算法模板非 xlsx/xls、损坏 xlsx、缺列 xlsx。
- 多唤醒：协议切换下的非法十六进制、奇数长度协议、脚本字符。
- 语音注册：仅在页面支持的垂类开启；先按 UI 选择学习命令词，再验证学习次数、模板数、上下限联动；不支持垂类验证开关隐藏或不可开启。

## 合成管理异常项

合成管理必须覆盖音频合成、播报合成和播报音频上传相关入口：

- 音频合成：项目名/备注必填、超长、脚本字符；Excel 导入缺列/损坏/错后缀；试听文本为空和超长。
- 播报合成：产品名必填、芯片/版本必选、产品名异常字符；版本配置默认音量、合成文本、播报控制新增、控制配置新增。
- 播报控制批量导入：必须通过 UI 的“导入/选择文件夹”入口验证，映射 xlsx 缺列、音频描述与文件名不匹配、缺音频、错后缀、超大小、采样率/声道/码率异常。若自动化无法给 `webkitdirectory` 注入真实目录，结论只能标记 `SCRIPT_LIMITATION`，由人工或增强脚本补测。
- 自定义音频/播报音频上传：非 mp3/wav、超大小、损坏音频、0 字节、多声道、采样率/码率越界必须走 UI 上传组件复核；直接调用 `/biz/audiofile/validate` 只能作为后端探测证据。

## 报告要求

报告必须包含：测试结论、测试目的、测试方案、用例和结果、问题与分析、证据目录。结果统计至少给出总用例数、明确拦截数、自动清洗数、放行风险数、脚本限制数，并按模块列出风险项的输入、UI 现象、最终分析。
