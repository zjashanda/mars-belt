# 3021 英文版本 UI-only 最小规则验证经验

本文沉淀 2026-06-15 3021 英文版本按中文最小规则重测的可复用逻辑。适用于用户要求“英文版本也按中文全链路方式覆盖当前支持垂类”的任务。

## 范围判定

- 每次执行都必须实时扫描 UI 当前矩阵：语言=`英文`、模组=`CSK3021`、当前可选垂类/版本/品类。
- 不能把中文垂类列表外推到英文；英文支持范围只以 UI 当前可选结果为准。
- 本轮实测结论：3021 英文当前仅开放 `通用垂类` 1 个垂类，版本 `通用垂类-V2.1.1_F3.0.1_A1.7.1.0`，其下 30 个可选品类。
- `风扇` 是本轮在 `通用垂类` 下选择的代表品类，不是“风扇垂类支持英文”。报告中必须写清“通用垂类 / 风扇代表品类”。
- 若后续平台新增英文独立垂类，重新扫描后按“每垂类一个代表品类”增量执行，不复用本轮 1 垂类结论。

## 打包矩阵

当前英文 `通用垂类` 能力回读：`dec_cmd=Optional`，`voice_regist=Unsupported`，`multi_wakeup=Unsupported`。因此按“只有基础功能”三包最小矩阵执行：

| 包 | 配置向量 | 目标 |
| --- | --- | --- |
| `pkg01_default_base` | 默认基础配置 + 英文基础算法模板 | 验证 UI-only 主链路、默认协议、英文唤醒和命令正例。 |
| `pkg02_left_base` | `timeout=1`、音量低值、短欢迎语、保存项低/关闭侧 | 验证左边界、唤醒进入和超时行为；不作为命令词正向包。 |
| `pkg03_right_base_protocol` | `timeout=60`、音量高值、协议波特率高值、DEBUG 日志、保存项开启 | 验证右边界、协议波特率变化和英文识别仍生效。 |

如果未来英文垂类支持多唤醒或语音注册，不能继续只跑上述基础三包，应回到 `references/platform_firmware_minimal_packaging_strategy.md` 的 3/4 包矩阵，并匹配英文专项模板和英文正式音频。

## UI-only 执行规则

- 产品创建、快速创建、基础配置、算法模板导入、生成 release 必须通过浏览器 UI 完成。
- API 只允许只读枚举、登录态、release 轮询、下载和证据采集；不得用历史 API 参数强写英文垂类、版本或配置。
- 同一个英文代表产品下生成多个 release，不为每个包新建产品。
- 生成后必须回读 release 实际配置；配置未入包不能算覆盖成功。
- 高值 slider 容易出现 UI 动作未真正落值的问题。若回读仍为默认值，必须修正 UI 拖拽/输入动作并重打替代包，旧 release 标为 superseded，不计入有效覆盖。

## 英文音频资产

- 英文运行态识别必须使用平台「合成管理 -> 音频合成」正式产物，不能把 `/fw/common/generateAudio` 试听产物作为主证据。
- 发音人必须带英文/英语标识；当前已验证 `Luna_x4云（英语） / x4_EnUs_Luna_assist`。
- 音频优先复用 `assets/audio/platform_synthesis/en/3021_fan_base/`；缺失时用 `scripts/py/listenai_platform_audio_synthesis_cache.py` 重新生成平台可见的音频合成项目。
- 英文基础验证最少包含：`Hello My Dear`、`Start Fan`、`Stop Fan`、`Volume Up`。额外音量/退出词可以作为扩展资产保留。

## 运行态判定

- 协议口波特率必须从固件 `web_config.json` 或 release 回读配置派生；右边界包可能不是默认 `9600`，本轮 `pkg03` 使用 `115200` 验证。
- 正常包需要校验：启动日志、`loglevel 4`、协议 RX/TX、默认唤醒词、代表业务命令、音量命令。
- `timeout<=1` 的左边界包按 timeout-only 处理：要求唤醒词识别、超时 marker、协议/启动链路可见；不要要求后续命令词正向识别，否则会把边界语义误判为失败。
- 汇总中必须区分：提交 release 数、superseded release 数、有效 release 数、下载有效 ZIP 数、烧录 PASS 数、运行态 PASS 数。

## 报告口径

报告必须直接回答两个问题：

1. 当前英文支持多少 3021 垂类？如果只有 `通用垂类`，必须说明其他中文独立垂类当前未开放英文版本。
2. 为什么只选择一个品类？因为策略是“每个垂类一个代表品类”，当前英文只有一个垂类，`风扇` 只是代表品类。

报告结构仍按 `references/platform_test_report_writing_standard.md` 执行：测试结论、测试目的、测试方案、测试用例和结果、测试问题与分析、证据文件。不要只写“英文风扇通过”。
