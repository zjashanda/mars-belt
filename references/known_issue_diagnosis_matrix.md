# 已知问题诊断矩阵

## 使用原则

本矩阵用于替代反复翻 `artifacts/` 原始日志。遇到相似现象时，先按矩阵执行最短闭环，再决定是否需要重新打包、烧录冒烟固件或回看历史证据。

诊断顺序固定为：

1. 判断是否是 UI 配置构造问题。
2. 判断是否是历史状态污染或测试流程问题。
3. 判断是否是设备/线序/声卡/控制链路问题。
4. 判断是否是固件/SDK 产物问题。
5. 判断是否是平台前端/后端缺陷。

报告中必须给出最终归因，不使用“可能有风险”“待确认”作为主结论。

## 快速分层

| 层级 | 典型证据 | 优先动作 | 最终归因口径 |
| --- | --- | --- | --- |
| UI 配置层 | UI 不支持、字段联动报错、非法值被 UI 保存 | 用 UI 当前页面重配，禁止 API 强写 | `平台 UI 限制` / `配置构造问题` / `平台前端校验缺陷` |
| 静态产物层 | `web_config.json`、算法模板、special 控制词、协议字段异常 | 下载包静态解析，最小依赖复包 | `配置构造问题` / `平台产物问题` |
| 烧录链路层 | 烧录超时、boot 不进、烧录后无启动 | 冒烟固件对照，检查唯一控制口径：switch1=电源、switch2=协议门控、switch3=boot、ACM0=烧录/日志 | `设备/控制链路问题` / `烧录链路问题` |
| 启动日志层 | 无启动日志、反复重启、Running Config 异常 | loglevel、上电门控、冒烟固件对照 | `设备链路问题` / `固件产物问题` |
| 协议层 | 无 RX/TX、播报不触发、协议波特率不匹配 | ACM2@9600 发已知帧，检查 `uut-switch2` | `协议链路问题` / `配置问题` |
| 声学识别层 | 无 Wakeup、单命令缺失、识别不稳定 | 平台合成音频 + 指定声卡 + 单词专项 | `声学/状态偶发` / `命令级匹配问题` |
| 专项状态机层 | 语音注册、多唤醒、左边界、主动播报异常 | 按专项规则裁剪用例，不跑错链路 | `测试用例问题` / `配置构造问题` / `功能缺陷` |

## 证据保留要求

每个问题闭环至少保留以下之一：

- 静态配置摘录：`web_config.json` / `cfg.json` / release 参数。
- 运行态 summary：烧录、启动、协议、声卡、专项能力结果。
- 串口关键 marker：不要把全文粘报告，保留文件路径和关键行。
- UI 证据：截图、导入预览、保存结果、下载状态。
- 对照证据：冒烟固件结果、控制变量包、单词专项结果。

如果问题最终沉淀成通用规则，必须更新本文或对应 `references/`，不要只留在 `artifacts/`。
